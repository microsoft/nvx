# 2.5 Device Topology, Transport, and Discovery

[Architecture documentation](README.md) >
[2. Virtual Machine Architecture](2-virtual-machine-architecture.md)

Table 2.7 lists the fixed devices. Every device uses virtio-mmio at a fixed
slot and offers the exact feature mask that Table 2.8 lists. The complete
device count, kind, bus, address, interrupt, feature policy, and queue shape
are validated before host resources are resolved.

**Table 2.7.** Fixed virtio-mmio devices.

| Device | Stable identity | MMIO range | IRQ | Presence |
| --- | --- | ---: | ---: | --- |
| Network | `net:microvm0` | `0xd0000000..0xd0000fff` | KVM/MSHV 10, WHP 5 | Optional |
| Host filesystem | `fs:microvm0` | `0xd0001000..0xd0001fff` | 6 | Reserved slot; attachment optional |
| Boot console | `console:microvm-virtio0` | `0xd0002000..0xd0002fff` | 7 | Optional |
| `distro` block | `blk:sandbox:distro` | `0xd0003000..0xd0003fff` | 4 | Optional, read-only |
| `scratch` block | `blk:sandbox:scratch` | `0xd0006000..0xd0006fff` | 11 | Optional, writable final role; absent in the RAM-backed overlay layout |
| Control console | `console:microvm-control0` | `0xd0007000..0xd0007fff` | 3 | Optional |

Placement is explicit rather than allocated sequentially, so an omitted device
never shifts another. All six slots are reserved, and the windows
`0xd0004000..0xd0005fff` and `0xd0008000..0xd0008fff`, IRQs 9, 12, and 13,
and the status words at `0x30010`, `0x30014`, and `0x30020` are unused.

**Table 2.8.** Guest-visible virtio features.

| Device | Device ID | Feature bits | Features |
| --- | ---: | --- | --- |
| Network | 1 | 5, 32 | `VIRTIO_NET_F_MAC`, `VIRTIO_F_VERSION_1` |
| Host filesystem | 26 | 28, 29, 32 | `VIRTIO_F_INDIRECT_DESC`, `VIRTIO_F_EVENT_IDX`, `VIRTIO_F_VERSION_1` |
| Boot console | 3 | 28, 29, 32 | `VIRTIO_F_INDIRECT_DESC`, `VIRTIO_F_EVENT_IDX`, `VIRTIO_F_VERSION_1` |
| `distro` block | 2 | 2, 5, 6, 9, 10, 28, 29, 32 | `VIRTIO_BLK_F_SEG_MAX`, `VIRTIO_BLK_F_RO`, `VIRTIO_BLK_F_BLK_SIZE`, `VIRTIO_BLK_F_FLUSH`, `VIRTIO_BLK_F_TOPOLOGY`, `VIRTIO_F_INDIRECT_DESC`, `VIRTIO_F_EVENT_IDX`, `VIRTIO_F_VERSION_1` |
| `scratch` block | 2 | 2, 6, 9, 10, 28, 29, 32 | `VIRTIO_BLK_F_SEG_MAX`, `VIRTIO_BLK_F_BLK_SIZE`, `VIRTIO_BLK_F_FLUSH`, `VIRTIO_BLK_F_TOPOLOGY`, `VIRTIO_F_INDIRECT_DESC`, `VIRTIO_F_EVENT_IDX`, `VIRTIO_F_VERSION_1` |
| Control console | 3 | 28, 29, 32 | `VIRTIO_F_INDIRECT_DESC`, `VIRTIO_F_EVENT_IDX`, `VIRTIO_F_VERSION_1` |

Each device offers exactly the features of Table 2.8, and the guest kernel
negotiates every one of them. Every device is a virtio 1.0 device with split
virtqueues, never packed ones. No device offers `VIRTIO_F_ACCESS_PLATFORM`
(bit 33): the machine has no IOMMU to translate a device's DMA, so the guest
gives each device guest-physical addresses directly. No console offers its
size (`VIRTIO_CONSOLE_F_SIZE`, bit 0), multiple ports, or emergency writes.

Every cold-booted microVM instantiates the host filesystem slot, even without
an attachment, so the slot is discoverable before capture and a snapshot can
record an explicit dormant state; a restore keeps the slot only when the
snapshot records it. Several host shares are children of one aggregate
attachment on that slot rather than additional devices. The control slot is
instantiated for a control console, either a live authenticated local
endpoint or an explicitly disconnected console. Other optional devices exist
only when configured.

The guest discovers fixed devices only from kernel command-line tokens that
the machine profile owns and emits in fixed address order; see
[Effective Command Line](5.1-boot-protocol.md#512-effective-command-line).
User arguments cannot inject alternate device declarations. Stable identity
comes from the machine profile and attachment contract, not from Linux device
enumeration order or names such as `/dev/vdX`; the guest maps each block role
to its device by MMIO address.

Saved state records the exact device inventory and transport contract.
Restore recreates that inventory in the same order and validates it against
the saved state before a virtual processor runs.
