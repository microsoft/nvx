# 4.3 Isolation and Resource Model

[Architecture documentation](README.md) >
[4. Guest Runtime Architecture](4-guest-runtime-architecture.md)

## 4.3.1 Identity and Credentials

The init owns execution identity and privilege separation from PID 1 and its
helpers. Workloads use the selected non-root user and primary group, without
the helpers' priority or capability privileges. `nvx` parses the contracts but
does not enforce this execution policy. The credential and launch sequence is
specified in the [guest-agent guidelines](../guest-agent-guidelines.md#own-the-executions).

The workload still sends ICMP echo, which carries ping, without a capability.
The guest's init, which runs before the guest agents in every guest mode,
opens Linux's unprivileged ICMP sockets to every group, with
`net.ipv4.ping_group_range` set to `0 4294967294`, so that any workload can
open a datagram ICMP socket for IPv4 or IPv6, which tools such as iputils'
`ping` do. Such a socket sends echo requests alone, and the host's egress
policy decides where they go, as [Packet
Forwarding](3.5-network.md#352-packet-forwarding) describes. The setting
belongs to the runtime, like the unprivileged port start: no workload changes
it. Raw ICMP sockets need `CAP_NET_RAW`, which the guest agents never grant and
an adapter's execution entry grants only while the guest's listeners are not
published. The setting lives in the guest's memory, so a snapshot of a guest
from an image that predates it keeps the kernel's default, `1 0`, which opens
no ICMP socket to an unprivileged workload.

## 4.3.2 Namespaces and Mounts

The space is VM-wide: one root, runtime filesystem set, hostname, machine ID
and resolver view. `nvx-init` implements the internal reference space and
switches into it once; executions need no separate root entry. This model
adds no per-execution mount, PID or UTS namespaces.

The root owns its mounts and view binds, and the init retains mapping handles
across the switch. After switching, shutdown ends the VM rather than unmounting
the root. The construction and ownership contract is in
[Construct the space](../guest-agent-guidelines.md#construct-the-space).

## 4.3.3 Cgroups and Resources

The VM is the resource limit. The init and its helpers have priority over
workload children, not a sibling cgroup reservation. This model configures no
cgroups or per-execution limits. The sole additional limit is the RAM upper's
cap; scratch and host-device access keep their own storage boundaries.

## 4.3.4 Enforcement Layers

The init applies the guest's credentials and space contract; the library does
not enforce its workspace, capture-admission or replay obligations. Host
devices independently enforce block mutability, network policy and
host-filesystem access. Guest mounts and routing cannot widen those host
permissions.
